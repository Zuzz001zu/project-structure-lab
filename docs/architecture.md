# Архитектура и обоснование структуры

## Тип проекта

Python-скрипт командной строки (CLI) для подсчёта статистики текста.

## Почему такая структура

| Папка / файл | Назначение | Почему выделено отдельно |
|---|---|---|
| `src/` | Исходный код | Код отделён от тестов, документации и служебных файлов — его легко найти и упаковать. |
| `src/main.py` | Точка входа | Отвечает только за ввод/вывод и аргументы командной строки. |
| `src/text_stats.py` | Бизнес-логика | Чистые функции без ввода/вывода — их просто тестировать и переиспользовать. |
| `tests/` | Автотесты | Тесты не попадают в рабочий код; pytest автоматически находит файлы `test_*.py`. |
| `docs/` | Документация | Подробные описания не перегружают главный README. |
| `assets/` | Статика и примеры данных | Входные файлы для демонстрации хранятся отдельно от кода. |
| `.github/workflows/` | CI | GitHub Actions автоматически запускает тесты при каждом push и Pull Request. |
| `README.md` | Главное описание | Первое, что видит человек, открывший репозиторий. |
| `.gitignore` | Исключения | Не даёт закоммитить кэш Python, виртуальные окружения и файлы IDE. |
| `LICENSE` | Лицензия | Определяет, как другие могут использовать код (MIT — свободная лицензия). |
| `requirements.txt` | Зависимости | Позволяет установить всё нужное одной командой. |

## Принципы

1. **Разделение ответственности** — интерфейс (CLI) отделён от логики подсчёта.
2. **Тестируемость** — логика вынесена в чистые функции.
3. **Стандартность** — раскладка `src/`, `tests/`, `docs/` привычна большинству Python-разработчиков.
4. **Масштабируемость** — новые модули добавляются в `src/`, новые тесты — в `tests/`, без изменения структуры.
